# xmip-core-library-net

Network primitives the capabilities share. What an address means to a gate
is the gate's; how it is written and read is here.

| Item | What it is |
| --- | --- |
| `accepting` | A listener's accept stopped: `woken` joins its thread once it has heard a knock, asked again for as long as it has not ended, `knock` connects to it, and `wakeable` is the loopback address a knock reaches a listener on every address at. The runtime's operate listener, the Storage node's server, the cluster's Event listener and the ACME challenge listener stop through it; until 2026-10-20 each knocked once, and a knock lost held a stop for good. The runtime's local-endpoint tests join their stand-in node's accept through it too: a client gone before the accept began is passed over by it (2026-10-21) |
| `address::parse` | An address as a transport writes it: bare, with a port, or IPv6 in brackets |
| `Network` | A network in prefix notation, and whether an address is inside it |
| `authority` | An authority as a URI writes it: `parse` into host and port, `host_of`, `with_default_port`, and `bracketed` for an IPv6 host in a `Host` header |
| `mac` | A hardware address in IEEE 802 notation: `parse` reads colons, hyphens, the dotted form or the digits alone, `notation` writes lowercase with colons |
| `percent` | Percent-encoding, RFC 3986's unreserved set: `encode`, and `encode_keeping` for a standard whose set is another (an event's wire attributes in HTTP headers), a lenient `decode` that leaves a broken escape as written, and `decode_strict` that refuses it where it is; `decode_pairs` and `encode_pairs`, a query or a form body as `name=value&…`, which HTTP's request target, a target's query, the AWS Query API and Azure's Shared Access Signature read and write through |
| `pipe` | `path_of`, where a named local endpoint is on this system: a name that is a path stays one, else `\\.\pipe\<name>` on Windows and a file in the temporary directory on Unix. The named pipe transport and a node's local operate listener find their endpoint by it |
| `Target` | A target as a URI writes it, read once and borrowed from its text: `parse` any `scheme://`, `under` the schemes a technology declares, `bare` for `host:port/path`, `naming_server` for either, `relative` for a path alone; the `authority` as written and `host_and_port` from it, the decoded `user` and `password`, the `path` and its `segments` — an empty one refused — the decoded `query` and `query_value`, the `fragment`, the `root` a path hangs under and the target `absolute` of its fragment. Every transport technology reads its send targets and its origins through it; until 2026-09-28 the transport capability split a target on its first slash with the query left in, twenty technologies stripped their scheme by hand and ten read a query again, most without decoding it |
| `uri` | A filesystem path as the path of a URI and back: `path_of` writes forward slashes and a leading slash (`/C:/in/a.edi`), `file_of` drops the slash before a drive. The file, SQLite and Unix-socket transports and the file, SQL-script and SQLite archives each wrote `path_of` until 2026-09-24 |
| `head` | A head as the line-oriented protocols write it — lines, then a blank line: `read_head` bounded at `MAX_HEADERS`, each line read by `read::line`, `header` that never searches the first line, `fields` that reads its header lines as names and values, and `write_fields` that writes them. HTTP and SSDP write and read with it; the transport capability held it until 2026-09-25, and SSDP wrote and read its own until 2026-09-28 |
| `read` | Reading off a connection, never more than Xmip holds: `until` a delimiter and `to_end` under a ceiling the caller names, and `line`, one line under `MAX_LINE` (64 KiB), its one CRLF or LF taken off, refused — never repaired — where it is not UTF-8. The head reader, the chunked body, STOMP, FTP, IMAP, SMTP, POP3, NATS, RESP, the SSH identification, syslog, MLLP and the dot-stuffed block read their lines through it, and TCP, a Unix socket, a named pipe and FTP's data connection read to the end through it; until 2026-09-27 each did it itself, unbounded, under three UTF-8 policies. `header` reads a framed protocol's fixed header whole, or nothing where the peer closed between messages, and refuses one cut short; AMQP, IBM MQ, NFS, OPC UA and SMB read theirs through it, where until 2026-09-28 each did it itself and took a header cut short for a clean close |
| `frame` | A frame as Xmip's own node-to-node protocols write one: its length, four bytes big-endian, then that many bytes, never more than `MAX_BODY`. `write` puts one on a connection in one write, `append` adds one to bytes about to be written so several go out in one write; `read` takes one off through `read::header`, `None` where the peer closed between frames. The Event link between nodes speaks it (`xmip-core-event`); Xmip Storage's wire wrote its own until it calls this |
| `ceiling::within` | The one refusal of a size over a ceiling, `"<size> bytes is over the <ceiling> <carrier>"`, the number and the carrier the caller's: every transport technology's send, encoder and loopback, the Playground, `read` and the HTTP body refuse through it. The transport capability held it until 2026-09-28, while `read` and the HTTP body each worded their own |
| `reply::code` | The code a line-oriented server's reply opens with — three digits, 100 to 599, then a space, a hyphen where the reply continues, or nothing. FTP and SMTP read it here; until 2026-09-27 each read it itself, and only FTP checked the range |
| `MAX_BODY` | The largest single Stream, body or message Xmip reads off one connection, 64 MiB. HTTP, the transport capability and every technology whose protocol states no maximum of its own read under it; until 2026-09-27 eleven places restated it, five of them as 16 MiB |
| `connect` | A TCP connection to a peer, the estate's one: every address its name resolves to tried in turn inside one deadline, the timeout on the connection's reads and writes, Nagle's algorithm off — a message written as a head and a body went forty milliseconds late on Linux, waiting on the peer's delayed acknowledgement — a refusal keeping its kind. The transport capability, the LDAP technology, the Open Policy Agent client and the introspection client connect through it; until 2026-09-27 the capability tried only the first address, the HTTP client gave each address the whole timeout, and LDAP wrote the loop a third time |
| `Endpoint` | An `http://` or `https://` URL, read through `Target`: host, port — the scheme's, or `or_port`'s where it names none — and path; `authority` as a `Host` header writes it, `address` to connect or bind to, `plain` to refuse TLS where the caller has none. `parse_under` reads it under the `Schemes` a technology riding on HTTP declares — `as2://`, `as4://`, `webdav://`, `msmq://`, `ws://` for plain, their `s` forms for TLS — so no technology rewrites a URL; AS2, AS4, `WebDAV` and MSMQ each did until 2026-09-28. The http transport read its targets with a parser of its own until 2026-09-25 |
| `http` | HTTP/1.1 on the wire, both halves: `Request` and `Response`, `write_request`, `read_response`, `read_request`, `write_response`, and `exchange` of one for the other over whatever connection it is handed — a socket, or one the http transport wrapped in TLS — and `exchange_kept` on a connection kept for the next, which says no `Connection: close` and whether the answer left the connection able to carry another. An answer is read by its length, its chunks or its end, a connection kept where a message names its own `Connection`. What the capabilities ask a service beside them with, and what every technology riding on HTTP calls; the http transport carried a second codec, which refused a chunked answer, until 2026-09-25. A 1xx, 204 or 304 answer is written without a length or a body, which is how the WebSocket handshake's `101` goes out; the handshake wrote its request and answer by hand until 2026-09-28. `http::date::rfc1123` writes the moment a `Date` or `x-ms-date` header carries; the http transport held it until 2026-09-28. An answer carries its `trailers`, a chunked one written and read with them, and `Version` names what a connection speaks and the ALPN identifier it is agreed by. A body is bytes; `Response::text` reads an answer a protocol writes as text — a service's XML or JSON, an error's detail — as UTF-8, and refuses a body that is not, never replacing a byte (ADR-0038). No TLS here: the connection is the caller's |
| `http2` | HTTP/2 on the wire, RFC 9113, both halves, over the same `Request` and `Response`: a `Client` that sends each request on a stream of its own and reads its answer, head, body and trailers; a `Server` that takes requests off their streams and answers them, and `serve` for a whole connection; `exchange` for one request on a connection of its own; `Client::going_away` says a server's `GOAWAY` has been read, so a connection kept between requests is let go. The preface and `sniff`, which tells it from an HTTP/1.1 request line and hands back what it read (`Replayed`); every frame type of section 6, SETTINGS and its acknowledgement, the stream states, flow control on the connection and per stream — a body waits at a shut window and resumes on `WINDOW_UPDATE` — `PING`, `RST_STREAM`, and `GOAWAY` sent and honored. HPACK, RFC 7541 (`http2::hpack`): the static table, the dynamic table with eviction, Huffman coding, the integer and string representations, held to every example of Appendix C. Synchronous and hand-written; server push off; no `Upgrade`, which RFC 9113 removed — `Client::io_mut` reaches the connection under it. `BoxedClient` and `BoxedServer` are the two over a boxed connection of any kind (`Boxed`), compiled here once, so a crate whose tests are unoptimized asks the code as it ships rather than compiling the generic halves again (the operate plane's calls, open problem 35) |
| `grpc` | gRPC's framing of a message on HTTP/2, once: `frame` and `unframe` (one byte compressed, four of length big-endian), `CONTENT_TYPE` and `CONTENT_TYPE_JSON`, the `grpc-status` and `grpc-message` trailers, and `code`, a status by its name or number. The gRPC logic technology frames with it, and so does the runtime's operate plane |
| `watched` | `Watched`, a long-lived connection read until its side ends or its peer falls silent: a read that waited its socket's short timeout is tried again, nothing lost, and between tries it looks whether its side is ending — shutting a socket from another thread does not wake a blocked read on every platform. The cluster's Event links and the operate plane read through it |
| `fixture` | For tests alone, behind the `test-support` feature a crate turns on from its dev-dependencies: `unheld` and `unheld_on`, a loopback address no one holds, for what a test starts later to bind or wants nothing listening at. Below every operating system's ephemeral range, a block of a hundred ports per test process, each call the next port of it that binds, so no connection the kernel numbers takes it and no two calls in one process share it. The block is held, its first port listened on while the process runs, and a process whose block another holds takes the next free one: until 2026-10-21 two test programs run at once shared a block whenever their process ids met in it, and one bound a port the other had found free (the runtime's plane test). The service tests held it until 2026-10-16, when it moved here; the runtime's tests, the operate plane's, the ACME tests, LDAP, the Open Policy Agent client, the transport capability, IBM MQ, SECS/GEM, COTP and this crate's `connect` bound `:0` and let it go, and two of the runtime's nodes then took each other's deliveries |

Until 2026-09-22 identification and authorization each carried their own
network type, and authorization read the peer's address under a name no one
wrote, so an address rule never matched a peer identified by name. The name
the peer's address travels under was declared here until 2026-09-24 and is
`context::property::PEER_ADDRESS` now, with every other name one layer writes
and another reads.

Until 2026-09-24 the authority was read by the transport capability and again
by two clients; the Open Policy Agent client, the OAuth 2.0 introspection
client and the Redpanda Admin API client each wrote HTTP/1.1 by hand; the
Ethernet frame, the DHCP message and the MAC identifier each read a MAC
address with a different set of spellings; and the http transport, the
API-key identifier, the form shape and the introspection client each
percent-encoded, three of the readers taking `%+f` as a byte. Each has one
copy here now, and the callers call it.

Moving a Stream over HTTP is the http transport's
([xmip-core-transport-http](https://github.com/IlleNilsson/xmip-core-transport-http)),
not this client's.

`architecture.toml` carries the maturity.
